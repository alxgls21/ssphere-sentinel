# SSphere Sentinel console: design spec

> **Status of this document.** The reference for exact values (tokens, geometry,
> per-component behavior). It is **not** a description of the code: where the
> build departs from it on purpose,
> [`architecture.md`](./architecture.md#departures-from-the-design-spec) lists
> the departures, and the code and [`design-system.md`](./design-system.md) win.
> Notably: stale content is tagged and only marks dim (not 60 % opacity on
> everything); thresholds are judged on the displayed value; wall mode, density
> modes, the inspector drawer and "NEW" tags are deferred and not built; the mock
> scenarios are `normal`, `healthy`, `partial`, `stale`, `slow`, `loading`,
> `empty`, `error`; the Overview counts servers, containers, probe targets and SNMP devices only, and its
> alert, event and fleet-latency figures are not drawn because the console API serves none of them
> for the Overview.

**Night Watch Console: SSphere Sentinel terminal-grade NOC design system (dark-first)**

Night Watch Console treats the screen as an instrument read in strict order by an operator who glances for two seconds at 03:00, decides whether anything is on fire, then triages and drills down with the keyboard alone. Structure: TIER 0 VERDICT (0-2 s): one tinted block holding a 24px status word with a 24px glyph, one 48px figure (entities needing attention) and a worst-first segmented bar of the whole fleet. TIER 1 QUEUE (2-10 s): a cross-domain Needs attention table sorted worst-first then newest-first, built only from state the backend really ingests today (servers, Docker containers, ICMP/TCP targets); every row is reachable with j/k and openable with Enter, so alert-to-detail is two keystrokes (1, Enter). TIER 2 CONTEXT (10-60 s): network latency/loss chart, fleet load, infrastructure health (domain bars plus per-site glyph strips). TIER 3 BACKGROUND: active alerts and recent events, both PLANNED (backend not implemented) and never counted in the verdict.\n\nTerminal in grammar, not costume: JetBrains Mono carries everything an operator scans (hostnames, IPs, counts, labels, nav, buttons, chart text, even the hero figures); IBM Plex Sans is reserved for prose (event and detail text, customer and site names, empty and error copy). Prompt-line breadcrumb ending in a live block cursor, one chevron as the single selection/active marker, tmux-style statusline with a NORMAL / INSERT / pending-chord mode block, indexed panels [1]-[6] that double as hotkeys, 1px hairlines, 2px radii, 5%-per-cell meters. No glow, scanlines, gradients, card shadows or decorative motion. Status is a closed alphabet of SVG shape + 4-letter word + colour (circle OK, triangle WARN, diamond CRIT, hollow square OFFL, bar IDLE, ring UNKN) because the mandated palette is only 8.4-9.1 delta-E apart for healthy/warning/critical under protan/deutan and cyan vs green is 11.5 (3.2 tritan): colour is never the sole channel and cyan never means OK. Healthy is quiet by size, absence of tint and absence of a word (not by dimming the mandated hex).\n\nThree trust behaviours from NOC practice: (a) a dead dashboard must never look healthy (stale guard at 45 s, NO DATA verdict at 120 s); (b) nothing moves under the operator (row order is locked while the queue is focused, queued updates surface as a pill, p pauses, while the verdict, title and badges always stay current); (c) honesty about maturity: everything is MOCK, features the backend lacks are PLANNED (dashed frame + chip), site assignment for servers/containers/targets (no Site link in the backend; only Device.site exists) is flagged as sample, and nothing invented is drawn (no container or fleet-wide trend lines, only a server's own history on its detail page; no container exit codes or restart counts; AGE degrades to last seen or an em dash).\n\nEngineering spine: one semantic token layer declared in a single Tailwind v4 `@theme static` block (so every variable is emitted to :root and ECharts/SVG read the same values through getComputedStyle), a vitest contrast test parsing tokens.css, a vitest ban on hex literals outside tokens.css, a /_ds dev route showing every ui/ component in every state, an in-house polling hook (the repo's useResource, no TanStack Query), per-panel data resources behind the SentinelApi port, a seeded mock with selectable scenarios, and a rem-based geometry that sums to exactly 900px at 1440x900 and scales to 1080p and 4K wall displays through the root font size. Dark-only for v1 (the token layering allows a light theme later; the mandated hexes are dark-tuned).\n\nPhasing: Built = shell, verdict, queue (order lock, pause, stale guard), five tiles, health, latency chart, fleet load, planned panels, command palette, shortcut sheet, /_ds. Deferred = InspectorDrawer (Space peek), NEW tags, wall mode toggle, density switch, prefers-contrast overrides.

## Visual signature

### Status alphabet: SVG shape + word + colour
Six shapes drawn as inline SVG on a 10x10 grid (never font characters; the fontsource latin subsets contain no U+25xx): circle = OK (healthy), triangle = WARN (warning), diamond = CRIT (critical), hollow rounded square crossed by a diagonal slash = OFFL (offline), bar 8.4x3.2 in text-muted = IDLE, ring in text-faint = UNKN. From 10px the circle, triangle, diamond and square carry a cue cut into the silhouette (a check, an exclamation mark, a cross, the slash) and the ring a question mark from 16px; the 6px mark is the plain shape. Offline is a presentation of critical, not a health status: HealthStatus keeps five members, and lib/status.ts maps a critical server flagged offline to the DisplayStatus 'offline'. Anything that decides (the verdict and its figure, attention counts, ranking, sorting, filters, chips, nav badges, document.title, the favicon, the severity edge) reads HealthStatus, so an offline server is critical to all of it; marks that describe an entity or a composition (tags, bars, count lines, strips, grid cells, legends, the Servers notice) show it apart. Each shape is followed by a fixed-width 4-letter mono tag (OK, WARN, CRIT, OFFL, IDLE, UNKN) or the more specific domain word (ONLINE, UNHEALTHY, RESTARTING, and OFFLINE for the offline state, which keeps its own glyph and tint). Rows and the verdict block carry a left severity edge in the worst child status colour (2px rows, 4px verdict). Healthy is quiet: no tint, no row edge, no word in dense strips, a 6px dot in cell strips, but always the exact #42D99B.

- **Used in:** StatusTag in tables, StatusGlyph in tiles, nav badges, tooltips, chart threshold labels, EntityCells, document.title and favicon (for example a diamond + 4 CRIT).
- **Why it is not a gimmick:** It is the accessibility mechanism. Measured (OKLab dE x100): healthy vs warning 8.4 protan, healthy vs critical 9.1 deutan, cyan vs healthy 11.5 normal / 3.2 tritan, so shape plus word must carry severity under colour-vision deficiency, grayscale, glare and 5 m viewing distance. The edge turns a table into a vertical severity band the eye runs down in under a second.

### Prompt-line chrome, live cursor and statusline mode block
Topbar breadcrumb is a shell path (sentinel > overview, or sentinel > acme > athens-dc when scoped) ending in an 8x14px block cursor that encodes connection state: solid primary = live, hollow = paused, 1 Hz stepped blink only while a request is in flight, struck through in warning or critical = stale or no data. The same chevron icon is the selection cursor in lists and the active-page marker in the sidebar (12% cyan tint row). A 24px tmux-style statusline shows a mode block: NORMAL (keys live, primary fill with bg-coloured text), INSERT (typing in a field, single-key shortcuts suspended) and a pending chord (g...), then the data-source line. ASCII > appears only inside the command-palette input. The prompt grammar is not used for verdict, loading or empty copy.

- **Used in:** Topbar, Sidebar, DataTable/AttentionQueue, EventLog, CommandPalette, StatusBar.
- **Why it is not a gimmick:** It answers three operational questions in about 300px: where am I in the Customer > Site hierarchy, is this data live, and are my single-key shortcuts armed. One consistent selection marker removes ambiguity about where keyboard focus is, the main failure mode of dense keyboard UIs.

### Indexed panels [1]-[6]
Every Overview panel header starts with its number in a bracketed mono keycap. Pressing the digit moves focus into that panel (tmux pane-select metaphor); the same digits appear in the shortcut sheet and the palette (Focus panel 3). Focused panel = primary-line frame plus a 2px primary outline when the region itself holds focus.

- **Used in:** Panel header, ShortcutSheet, CommandPalette.
- **Why it is not a gimmick:** The label that names a panel is also the key that reaches it, so the screen becomes a keyboard map with nothing extra to learn or render, and operators get a shared vocabulary ('check panel 3').

### Worst-first segmented bars, cell meters and glyph strips
One mark grammar built on a 2px gap: SegmentedBar orders segments crit, offline, warn, unknown, idle, ok from the left (6px in tiles, 8px in the verdict and health rows, 2px surface gaps, 2px radius on outer ends only, every non-zero segment at least 3px wide; unknown is a hollow outline, idle a half-height bar and offline two thin bars with a 2px break, so the bar never leans on color alone). CellMeter shows utilisation as 20 cells of 5% (8px tall, 2px gaps) in cyan below 80%, amber from 80%, red from 95%, with a triangle or diamond glyph appended once a threshold is crossed. EntityCells draws one glyph cell per entity (10px wide, 12px pitch) worst-first for a site row, collapsing to a SegmentedBar plus counts above 20 entities. Each has a block-text twin (for example the 20-cell meter as a string of block characters) in its aria-label and in the y (copy row) clipboard text, so a row can be pasted into a ticket.

- **Used in:** Verdict, StatTile, Infrastructure health (domain rows and site rows), Fleet load, later SNMP interface utilisation and Servers/Customers screens (EntityCells grid variant).
- **Why it is not a gimmick:** Quantised cells read like a terminal progress bar yet compare more easily across rows than a smooth fill; fixed worst-first order means red is always at the same place; the 3px minimum stops one failing host disappearing in a fleet of 124.

### Trust layer: stale guard, refresh hairline, per-panel data age
Freshness is computed from the client time of the last successful load and the response generatedAt. Over 45 s the topbar FreshnessChip becomes STALE (struck cursor, warning text); over 120 s, or when every domain resource has failed, the verdict is replaced by an UNKN ring and the words NO DATA, the hero figure becomes an em dash and numbers dim to 60%. A 1px hairline under the topbar fills left to right over the poll interval (transform scaleX) as the real heartbeat. Every panel header shows its source and refresh interval ('mock · 15s'). While the queue is focused its row order is locked and a pill reads '3 updates, apply (r)'; the verdict, title and badges keep updating.

- **Used in:** Topbar, VerdictHero, Panel header, AttentionQueue, document.title, favicon.
- **Why it is not a gimmick:** On an unattended wall display the worst failure is a frozen screen that still says all green. The hairline replaces a looping pulse dot with a functional progress indicator that is static under reduced motion.

### Provenance line styles: solid, hatched chip, dashed
Data trust is encoded in border and fill so it survives screenshots. Solid 1px frame = backed by implemented ingest data (mock for now). A single hatched MOCK DATA chip (135 degree stripes of --color-hover on --color-raised, neutral, no new hue) in the topbar plus a quiet 'mock' tag per panel and tile. Dashed 1px --color-border-strong frame + PLANNED chip (dotted-ring glyph, dashed border) + values in text-muted + disabled actions with a reason + one footer sentence = feature the backend has not implemented (alerts, events, SNMP collection, topology, site links). Panel requires a features prop, so an unlabelled panel does not compile.

- **Used in:** Every panel and tile; sidebar PLAN tags; palette PLANNED group.
- **Why it is not a gimmick:** The brief demands the UI never imply unfinished features are operational. The markers are always on, redundant across shape, hatch and words, derived from config/features.ts and the API source so they disappear per feature as the backend ships.

## Typography

- **Sans:** IBM Plex Sans (static 400 and 600): prose only (event and detail text, customer and site names, tooltip prose, empty and error copy, screen and dialog titles)
- **Mono:** JetBrains Mono (static 400 and 500): everything an operator scans (hostnames, IPs, counts, hero and KPI figures, tags, labels, nav, buttons, tables, chart text)

**Packages**

- @fontsource/jetbrains-mono: import '@fontsource/jetbrains-mono/latin-400.css', 'latin-500.css', 'latin-ext-400.css', 'latin-ext-500.css', 'greek-400.css', 'greek-500.css' (verified against the published package: it ships cyrillic, cyrillic-ext, greek, latin, latin-ext, vietnamese subset files)
- @fontsource/ibm-plex-sans: import '@fontsource/ibm-plex-sans/latin-400.css', 'latin-600.css', 'latin-ext-400.css', 'latin-ext-600.css', 'greek-400.css', 'greek-600.css' (verified: ships greek)
- Verified: @fontsource/ibm-plex-mono ships NO greek subset (cyrillic, cyrillic-ext, latin, latin-ext, vietnamese only), which is why it is not the mono face: Greek customer, site and target names (this project's likely estate: Athens, Thessaloniki, Patras) must render in the mono columns without a mismatched fallback. Add cyrillic-*.css imports only if a deployment needs them.
- Import the per-subset static files from src/main.tsx, never the package root or the variable packages: each subset CSS carries a unicode-range so the browser fetches only the subsets a page uses, Vite bundles the woff2 files into dist, and the critical path is 4 latin files (2 per family). Zero CDN or Google Fonts requests (air-gap safe).
- Verified: the latin subsets contain no U+25xx geometric shapes, box-drawing or block elements, so every status shape, meter, cursor and sparkline is SVG or CSS; unicode block characters appear only in aria-labels and clipboard text.

**Pairing:** Two families, both SIL OFL and self-hosted. JetBrains Mono is the console voice: tall x-height and open apertures keep 12px dense tables legible, digits are inherently tabular, 0/O and 1/l/I are unambiguous for hostnames and container ids, and it covers Latin, Latin Extended, Greek and Cyrillic. Set font-variant-ligatures: none (JetBrains Mono ships code ligatures; '->' and '!=' must be shown literally) and font-feature-settings: 'zero' 1. IBM Plex Sans has the same rectilinear construction and covers Greek, so mixed rows (mono entity + sans detail) do not look uneven. Rule: if a machine produced it or it labels a machine value it is mono; if a person wrote it it is sans. Stacks declared in @theme static: --font-sans: 'IBM Plex Sans', ui-sans-serif, system-ui, sans-serif; --font-mono: 'JetBrains Mono', ui-monospace, 'SF Mono', Menlo, Consolas, monospace. Mono advance is 0.6em, which all geometry below assumes.

**Numerals:** Mono digits are tabular by construction: every column of numbers is mono and right-aligned with fixed decimals per column. Hero (48px) and KPI (28px) figures are JetBrains Mono 500 with negative tracking (-0.04em and -0.03em) to offset the loose 0.6em advance at display size: a deliberate, documented deviation from the dataviz guidance that large numerals use proportional figures, accepted to keep a single voice and because figures are at most 3 digits (cap at 999+). Units sit beside the figure in mono 12px fg-muted (142 ms, 91 %). Formatting lives in lib/format.ts: integers under 10,000 are never abbreviated (Intl.NumberFormat separators); percent 0 decimals at or above 10 and 1 below; latency 0 decimals at or above 10 ms else 1; bytes IEC (GiB); rates in bits (Mb/s); durations compact (6m, 1h 12m, 3d 4h); clocks 24-hour HH:mm:ss, UTC with a Z suffix by default, local via z; relative age in tables, absolute timestamp in tooltips; minus is U+2212; a missing value is an em dash, or the words 'no data' where a sentence or an accessible name needs them (the latency tooltip, table and spoken sample write them), never 0 or NaN. Minimum rendered size anywhere is 11px. All sizes are rem tokens (px below at 1rem = 16px); wall mode scales the root font size.

### Chart categorical colors

- Slot 1 cyan #64D8E8 (= Primary): the metric or entity in focus (p95 latency, 'in' direction)

### Contrast notes
All values computed by a WCAG 2.x relative-luminance script, with tints and lines computed as colour mixes over #10161B, plus OKLab dE x100 with Machado 2009 CVD simulation. TEXT: fg 13.37, fg-muted 8.30, fg-faint 5.98 on panel; the weakest allowed pairing (fg-faint on the selected/flash tint) is 4.69:1, so every information-bearing text token passes AA (4.5:1) on bg, panel, raised, hover, selected and all four status tints (lowest 4.69). Status and primary text: 6.15 (critical) to 10.87 on panel (offline 7.00); allowed only on bg, panel, raised, hover, selected or its own 12% tint (critical on own tint 5.30, offline 5.83). NON-TEXT (3:1 against panel): focus ring primary 10.87; status glyphs 6.15-10.87 (offline 7.00); unknown ring 5.98; idle bar 8.30; every chart series 4.17-10.87 (series-3 lowest); border-control 4.10 (and 3.22 on the selected tint, 3.55 on hover, 3.84 on raised, 4.44 on bg); seq-2..5 3.59-10.87; seq-1 is the ordinal light-end step at 2.19 (floor 2.0). Decorative hairlines (border 1.35, border-strong 1.94, chart-grid 1.17, lines 1.95-2.76) are exempt and never the sole carrier of meaning. CVD (dE x100 normal / protan / deutan / tritan): healthy-warning 19.4 / 8.4 / 11.3 / 23.7; healthy-critical 31.9 / 22.3 / 9.1 / 35.9; warning-critical 21.0 / 21.5 / 15.4 / 17.3; primary-healthy 11.5 / 10.5 / 9.9 / 3.2: below a 15 floor in several cases, therefore shape plus word are mandatory and cyan never carries a state; offline (a cool low-chroma hue) against critical 19.2 / 14.3 / 14.0 / 23.6, warning 24.3 / 22.9 / 25.3 / 17.5, healthy 21.7 / 18.3 / 14.2 / 14.3 and primary 15.6 / 14.9 / 11.2 / 15.9 (a test holds every one to 10 or more), and against fg-muted 7.2 / 7.1 / 7.1 / 4.6 and fg-faint 7.7 / 7.3 / 6.9 / 4.6 (floors of 6, and 4 under tritanopia, where a blue-violet drifts toward grey), so its silhouette and word carry the state first; no cyan mark is placed beside a green status mark (Fleet load shows glyphs only at 80%+, never OK). Categorical adjacents: p-s2 24.4 / 24.5 / 26.0 / 17.9; s2-s3 25.7 / 13.9 / 14.3 / 27.5; s3-s4 17.6 / 14.4 / 13.7 / 22.2; slots 1-3 all-pairs worst 13.9 CVD; s2 vs s4 collapses under CVD (1.8 protan), hence the 3-series cap for all-pairs forms and direct labels for a 4th; slate vs s3 4.7 deutan and slate vs s4 4.7 tritan, hence slate is never plotted with them. Rules encoded in code, not review: (1) no status colour utility (text, bg, border, fill, stroke, ring and outline variants of healthy, warning, critical and offline, with their -tint and -line) outside ui/status, ui/meters and charts (vitest grep); (2) styles/tokens.test.ts parses tokens.css and asserts every text token on every surface and every non-text token on panel, and offline's derived tint and line, chroma and separation under simulated colour vision; (3) no hex or rgb literals outside tokens.css (vitest grep); (4) prefers-contrast: more maps fg-muted and fg-faint to fg and hairlines to border-control; forced-colors keeps shapes through currentColor/CanvasText and enables chart decals. Implementation: declare every token inside one `@theme static { --color-*: initial; ... }` block (drops Tailwind's default palette so stray utilities cannot compile, and emits all variables to :root for getComputedStyle).

**baseUnitPx**

4

**scale**

Allowed steps: 2 (hairline gaps only), 4, 8, 12, 16, 24, 32, 48 (p-1 = 4 ... p-3 = 12). Component constants (default density): control and table row 28, panel header 32, panel body padding 12, page padding 12, panel gap 12, inline gap 8, glyph-to-text gap 6, tile padding 12, topbar 44, status bar 24, sidebar 208 expanded / 56 rail, index chip 16, icon 16. **breakpoints**

Tailwind v4 --breakpoint-*: sm 640, md 768, lg 1024, xl 1280, 2xl 1440. 2xl and up: the reference layout above, sidebar expanded by default. xl (1280-1439): same layout, sidebar defaults to the 56px rail (preference persisted). lg (1024-1279): rail only; strip becomes two rows (verdict full width 88px as one horizontal line: figure + word, fleet bar, counts; then 5 tiles at 1fr); Needs attention spans 12 columns and shows 8 rows (310px); charts 6/6 (324); Health, Alerts, Events become a 4/4/4 row at 308px. md (768-1023): sidebar is an off-canvas drawer, 6-column grid, tiles 3 + 2 (second row spans 3 each), queue full width, charts 6/6, then Health, then one collapsed 'PLANNED - backend not implemented (2)' accordion holding Alerts and Events. Below 768: single column with the mobile order in mobileNotes. Wall mode (deferred) is a state (w), not a breakpoint: html[data-wall] sets font-size: clamp(16px, min(100vw / 90, 100vh / 56.25), 40px), a valid expression (verified: 1440x900 gives 16px, 1920x1080 gives 19.2px = x1.2, 2560x1440 gives 25.6px, 3840x2160 gives 38.4px = x2.4; the design box is 1600x900 css px at 1080p, 1440p and 4K). The wall header (32px) replaces the 44px topbar and the sidebar is hidden, so flexible rows gain 12px. Below a 1600x900 design box the clamp floor of 16px applies and the content area scrolls. A vitest asserts that tokens.css contains the exact clamp string and that lib/wall.ts returns the values above; ECharts reads the computed root size and re-initialises on change. pointer: coarse switches rows and controls to 44px and hides keycap hints; hover: none turns tooltips into tap popovers.

**density**

Three modes through tokens on <html data-density>: compact 24px rows (opt-in, deferred), default 28px (tables, event lines 24, nav items), comfortable 32px (deferred); pointer: coarse forces --hit 44px regardless. Components consume only var(--row-h), var(--ctl-h), var(--panel-head), var(--pad), var(--gap), var(--hit); none hard-codes a density value. Density never changes type sizes below the 11px floor; it changes row height and vertical padding only. Whitespace is spent separating zones (12px gutters), not inside rows, so the eye can run a column of glyphs without gaps.

## Components

### AppShell
- **Purpose:** Page frame and providers: skip links, landmarks (banner, navigation, main, contentinfo), sidebar + topbar + content + status bar, global hotkey provider, aria-live Announcer, wall-mode controller (deferred).
- **Variants:** default; rail (sidebar collapsed); drawer (below 768px); wall (deferred: sidebar and topbar controls hidden, 32px wall header with verdict word, UTC clock, freshness and MOCK chip; cursor hidden after 5 s idle).
- **States:** loading (shell paints immediately, panels show skeletons), stale (topbar chip + verdict override), paused (PAUSED pill), offline (navigator.onLine false adds an OFFLINE segment to the status bar).
- **Accessibility:** First two tab stops are 'Skip to main content' and 'Skip to Needs attention'; each Panel is role=region labelled by its title; main has tabindex=-1; focus returns to the previously focused row after overlays close and after returning from a detail screen (selection restored by entity id). Announcer is one polite region that speaks only verdict changes, new CRIT entries and stale/no-data transitions, rate-limited to one per 5 s; assertive is never used.

### Sidebar / NavItem
- **Purpose:** Primary navigation for the 9 screens, rendered from the existing NAV_ITEMS registry (Overview, Servers, Docker, Network, SNMP, Topology, Alerts, Customers & Sites, Settings).
- **Variants:** expanded 208px (icon 16px, label in --text-data, right slot = worst-state StatusGlyph + count for implemented domains, or a PLAN tag for a screen the backend does not implement, plus the g-key keycap on hover/focus); rail 56px (icons with tooltips showing label + g-key and a 8px worst-state glyph at the icon corner); drawer. Footer: Cmd/Ctrl+K, ? shortcuts, w wall mode, [ collapse, 'v0.1 - MOCK'.
- **States:** active (primary-tint fill + 2px primary left edge + aria-current=page), hover, focus-visible (2px primary inset outline), planned (label in fg-muted + PLAN tag; the route renders the existing placeholder that explains what is missing and links to docs/snmp.md where relevant). Badges are computed only from implemented data.
- **Accessibility:** nav landmark; roving tabindex (Tab enters once, Up/Down move, Home/End jump) so the sidebar is one tab stop; badge accessible names such as 'Servers, 1 critical'; planned items announce 'planned, not implemented in backend'; collapse state persisted in localStorage inside try/catch.

### Topbar
- **Purpose:** 44px context bar: BreadcrumbPrompt with the live cursor, ScopePicker, TimeRange, FreshnessChip, UTC clock, MockChip, PaletteTrigger, plus the 1px refresh hairline on its bottom edge.
- **Variants:** Left to right: sidebar toggle, breadcrumb prompt (sentinel > overview; the last segment in fg, earlier segments fg-faint), ScopePicker (two native selects, Customer and Site, default 'All customers'; scopes every panel; hidden in the live adapter until Server and NetworkTarget have a Site link), TimeRange segmented control (15m 1h 6h 24h from RangeKey, key t; scopes only range panels and its tooltip says so), FreshnessChip, UTC clock (z toggles local), MockChip (hatched, shown while api.source is mock), PaletteTrigger (240px, styled as the prompt: > search or run...  Cmd/Ctrl+K). Below 1024px the breadcrumb collapses to the screen title and scope/time fold into one Filters button.
- **States:** FreshnessChip: live (solid cursor + 'updated 3s ago'), fetching (stepped blink + 'updating'), paused (hollow cursor + 'PAUSED 41s'), stale (struck cursor, warning text on warning-tint, 'STALE 52s' after 45 s), no data (struck cursor, critical text on critical-tint, 'NO DATA 2m' after 120 s). The chip never uses the OK/WARN/CRIT shapes (those are reserved for entity health).
- **Accessibility:** banner landmark; the chip is role=status (polite) and announces state changes only, never every tick; the clock is aria-hidden with a visually-hidden time updated each minute; TimeRange is a radiogroup; native selects.

### StatusBar
- **Purpose:** 24px tmux-style footer, always visible except on mobile.
- **Variants:** Left: mode block (NORMAL = primary fill with bg-coloured text, INSERT while a text field is focused, a pending chord such as 'g...' that auto-cancels after 1.2 s or Esc), then the source line ('MOCK - mock://fixtures v1 - MockApi (no backend read APIs) - scenario normal', flipping to 'LIVE - https://host/api/v1'). Right: 'next poll 12s' (PAUSED when frozen), context key hints (p pause, r refresh, ? keys), UI version. Mobile keeps only mode-less source and clock.

### HotkeyProvider + ShortcutSheet
- **Purpose:** One keyboard layer (about 60 lines: single keys, modifiers, 'g x' sequences with a 1.2 s timeout) and a ? sheet generated from the same registry so documentation cannot drift.
- **Variants:** Scopes global, screen (overview), panel (list or chart focused), overlay (palette, drawer); inner scopes win and overlays swallow everything except Esc. Letters and digits are matched by event.code (KeyG, Digit1) so Greek and Cyrillic layouts work; punctuation shortcuts ([, ?, /) match event.key and each has a non-punctuation alternate (Ctrl/Cmd+B, Ctrl/Cmd+/, palette commands). - **States:** sequence pending (mode block shows 'g...'), disabled (Display menu toggle 'Single-key shortcuts: on/off').
- **Accessibility:** Single-character shortcuts are ignored while focus is in an input, textarea, select or contenteditable and when Ctrl, Alt or Meta is held; they can be turned off (WCAG 2.1.4) while Ctrl/Cmd+K and in-component arrows remain; every shortcut has an on-screen or palette equivalent; the sheet is a native dialog with a real table of keys. Space is never bound globally (it keeps native button activation and scrolling); on a focused queue row Space is the deferred peek.

### CommandPalette
- **Purpose:** Ctrl/Cmd+K launcher for navigation, entity jump and actions; with an empty query it lists the current top problems, so it doubles as a triage launcher.

- **States:** empty query, typing, no results ('No match. Try @ for entities'), loading entity index (skeleton lines), disabled item (selectable; Enter shows 'Not implemented in backend' in the status bar).

### Panel
- **Purpose:** The universal container (header, body, optional footer, state slot).
- **Variants:** standard; planned (dashed frame + PLANNED chip + footer sentence); focus-owner (primary-line frame); flush (tables, no body padding). Required prop features: FeatureId | readonly FeatureId[] (a missing prop is a TypeScript error): the panel reads api.source for the 'mock' tag and isUnimplemented() from config/features.ts to decide planned (planned only when every feature is unimplemented).
- **States:** ready, loading (skeleton after 150 ms), refetching (previous content at 60% opacity, no layout change), empty, error (inline ErrorState with Retry, 'Showing data from 14:03:10Z' and the last good data kept visible beneath a non-blocking banner), stale (content at 60%, STALE chip), order-locked (queued-updates pill).

Not implemented in the backend yet.'; the [n] keycap is aria-hidden and the hotkey is exposed through aria-keyshortcuts; errors use role=alert once then role=status; skeletons are aria-hidden with a visually-hidden 'Loading <title>' and aria-busy on the region.

### StatusGlyph + StatusTag
- **Purpose:** The single way to show a health state: inline SVG shapes (circle, triangle, diamond, hollow square, bar, ring, plus the dotted ring used only by the PLANNED and NOT CONNECTED chips) in sizes 6/10/12/16/24, coloured through currentColor so forced-colors and print work; from 10px the circle, triangle, diamond and square carry a cue cut into the silhouette (check, exclamation, cross, slash) and the ring a question mark from 16px, while the 6px mark is the plain shape; StatusTag adds the fixed-width 4-letter word; StatusLegend lists the states as glyph + word pairs.
- **Variants:** glyph-only (needs an accessible name), glyph + word (compact, no tint), tag (word on the status tint, 6ch wide so a column of tags is a clean scan line), domain-word (ONLINE, UNHEALTHY, RESTARTING... replacing the class word where more specific, glyph unchanged; OFFLINE is the domain word of the offline state and comes with its own glyph and tint), legend (StatusLegend: every state in the order of the alphabet, OK, WARN, CRIT, OFFL, UNKN, IDLE; the Overview health panel shows OK, WARN and CRIT always and the other states only when a mark in the panel is drawn in them). Future Cytoscape nodes reuse the same alphabet as node shapes (ellipse ok, triangle warn, diamond crit, hollow ellipse unknown); the rounded rectangle is offline's, so idle needs a different node shape.
- **States:** static; a new CRIT row gets a single 1.2 s inset critical outline fade (no background change, never a loop); selected row suppresses the tint to keep contrast; planned (dotted-ring glyph, fg-muted).
- **Accessibility:** decorative (aria-hidden) when adjacent to its word; standalone use carries role=img with aria-label such as 'critical' or 'offline' (one map of spoken names: ok, warning, critical, offline, unknown, idle; the compact word is for scanning, so strips, queue rows and palette rows say 'offline' and 'critical', and a grid cell says 'offline' in full beside the compact word of the other states); status colour is used on the glyph and word only where contrast is at least 4.5:1.

### Meters (SegmentedBar, CellMeter, Sparkline)
- **Purpose:** Plain SVG/DOM mark primitives, no chart instance: composition by state, utilisation, and a trend line over a series that may have gaps.
- **Variants:** SegmentedBar: 6px or 8px tall, order crit, offline, warn, unknown, idle, ok, 2px surface gaps, 2px radius on outer ends only, minimum 3px per non-zero segment, unknown a hollow outline, idle a half-height bar, offline two thin bars with a 2px break (2px halves in a 6px bar, 3px in an 8px one), no gradient or hatch, planned variant = dashed outline with the text 'no SNMP data', segmentTitles (default on) puts a native title on each segment and is off where a row Tooltip already describes the bar. CellMeter: 20 cells of 5%, 8px tall, 2px gaps, fill cyan below 80, amber 80-94, red 95+ (UI defaults), track = 12% tint of the fill hue, glyph appended at 80+, value printed right in --text-data-strong, no sample = empty cells + 'no data'. Sparkline: 64x24px, any number of points, 2px stroke in --color-series-other, the newest real sample an 8px primary dot inside a 10px panel-colour ring, fixed 0-100 domain for percentages (a domain prop overrides it); one entry per bucket with null where no sample arrived: a gap breaks the line (never bridged), a lone sample is a 3px dot, and a series that ends on a gap has no end dot but a hollow mark (3px radius, fg-muted stroke, panel fill) on its last sample and a dashed 1px tail in fg-faint under the 0% level to the newest bucket; a stale series (no longer being refreshed) ends in the same hollow mark and says last where it would say now; used only where the backend stores history: the network success rate (Net targets tile) and, on the server detail Summary, a server's CPU, RAM and disk.
- **States:** zero total renders an empty hairline track; a segment carries a native title ('WARN 2 of 40') on hover, unless its bar sits in a row with a Tooltip (segments are not focusable). ### IncidentTimeline
- **Purpose:** The incidents among the events of a range, one 24px lane each on a shared time axis: what failed, what recovered, what is still open. The second view of the Recent events panel (Log | Timeline tabs in its header), from the same request, so it knows nothing the log does not show.
- **Variants:** Incidents are derived client-side from SentinelEvent[] (no API of its own): a warning or critical event that nests under nothing opens one, the first healthy event of the same subject nested under it at any depth closes it (the recovery of another subject, or of none, does not), info events never do, nothing claims an acknowledgement because an event carries none, and a recovery whose failure is not among the events (older than the range, or beyond the newest events the panel holds) is an incident with no known start, severity or duration. Lanes: ongoing first (critical before warning), then resolved, most recent start first. Above the lanes a 16px summary line ('2 ongoing · 5 resolved') and a 16px axis row labelled at its two ends only (HH:mm, a Z for UTC, led by the weekday when the axis runs across midnight); the axis is the topbar range ending when the events were read. A lane has three columns: the subject (4rem in a panel under 24rem, 7.5rem up to 32rem, 10rem from there), the track, and a word with a duration (6.75rem). The track holds a severity glyph for how the incident began (diamond for critical, triangle for warning), a bar of 8px for how long, and a mark for how it ended: an ongoing incident is a solid bar in the severity colour that runs to the right edge and stays open (a chevron), with the word ONGOING in the severity colour and its duration so far; a resolved one is a thin line on the severity tint that ends in the OK mark, with RESOLVED in fg-muted and how long it lasted. A chevron at the left cuts a bar that began before the axis. A duration reads '<1m', '28m', '1h 5m'. Nothing animates.
- **States:** empty ('No incidents in the last 1h'); holding (hovering the timeline or focusing a lane keeps the lanes, and the moment they are measured against, as they are, and what arrives meanwhile waits behind an 'N new' pill that releases it and moves focus to the first lane); a different range or scope shows at once. At the 178px panel of the 1440x900 layout the summary and axis take 32 of the 120px body, so three whole lanes show and the rest scroll.
- **Accessibility:** the lanes are one tab stop (a roving stop: Up, Down, Home and End move between them) in a list named 'Incident timeline', described by its window and timezone ('Last hour, 13:05 to 14:05. Times are UTC.'); each lane is named by one sentence ('pir-vpn: critical incident, started 13:43, ongoing for 22 minutes'; 'acme-vpn:443: incident that began before the last hour, resolved at 13:25' when the start is unknown); hovering or focusing a lane opens a tooltip with severity, started, recovered, duration and the opening and recovery messages, which is supplementary: the Log view carries every message.

## Charts

**theme**

Apache ECharts 6, modular: import * as echarts from 'echarts/core'; LineChart and BarChart from 'echarts/charts'; GridComponent, TooltipComponent, AxisPointerComponent, MarkLineComponent, AriaComponent from 'echarts/components'; CanvasRenderer from 'echarts/renderers'; echarts.use([...]) in the existing charts/echarts.ts (MarkAreaComponent is already registered there but unused on the Overview; DataZoom and Heatmap/VisualMap are added by the Network and SNMP screens later). Failed probes use a line series with symbol 'diamond' and zero line width, so no ScatterChart is bundled. The chart module is a React.lazy chunk so the shell, verdict and queue paint before any chart code loads. One registered theme named sentinel is built at runtime by buildChartTheme() reading getComputedStyle(documentElement) for --color-*, --font-mono and the root font size (this works only because tokens are declared with @theme static): backgroundColor transparent (the panel is the surface), textStyle fontFamily from --font-mono 11px in fg-faint, color array [primary, series-2, series-3, series-4, series-other], animationDuration 400 / animationDurationUpdate 300 / cubicOut, aria.enabled true, useUTC following the global UTC/local toggle. Wait for document.fonts.load('11px JetBrains Mono') before the first measure. Canvas with devicePixelRatio auto, ResizeObserver resize, dispose on unmount; in wall mode text and symbol sizes are multiplied by the root-size ratio and the chart is re-initialised. There is no second colour definition: a vitest asserts the resolved theme equals the tokens, and chart definitions reference series slots by index or status tokens by name, never hex.

**lineAndArea**

Overview chart [2] Network latency and loss (range-scoped by the topbar: 15m and 1h use 1-minute buckets, 6h 5 minutes, 24h 15 minutes): two stacked grids sharing one time axis with a linked crosshair (axisPointer.link on all x axes), never a dual axis. Top grid: p95 latency in primary cyan 2px (round join and cap, the series operators act on) and p50 in slate (--color-series-other) 2px; bottom grid (48px): packet-loss columns in series-2 azure. Measurements are discrete: smooth false and connectNulls false, so a missed or failed probe is a gap in the line plus a small critical-colour diamond (the CRIT glyph shape) on the loss-grid baseline. Each grid draws its warn limit as a SOLID 1px line in warning at 60% opacity, labelled on the line in fg-faint at full opacity with a panel-colour edge: 'warn 150 ms (UI default)' on the latency grid and 'warn 2% (UI default)' on the loss grid (dashed is reserved for 'planned', so a limit is solid). A limit is a markLine on a series of its own that has no data (ids 'reference:latency' and 'reference:loss', referenceLine() in charts/timeSeries), not on p95 or loss, so it stays when the legend hides every data series and is neither a legend entry nor a tooltip row. Its label goes in whichever corner of the line (start or end, above or below) the data leaves clear, the start above the line by default. Symbols are hidden except the last point and the hovered point (8px filled dot with a 2px panel-colour ring). Every p95 sample over 150 ms (judged as displayed, to whole milliseconds) carries an 8px warning triangle 10px above it and every loss sample at or over 2% (to one decimal) a triangle 7px above its column, so the state is a shape and not only a colour; the single worst p95 spike is labelled with its value and time ('212 ms at 13:41Z', 12px in text colour, aligned so it stays inside the plot) above its triangle. Area fill (10% opacity of series 1) is used only for a single-series drill-down, never with two series. Direct end labels on p95 and loss in --text-data-strong (labels never wear series colour; dropped in a narrow container); the legend is an HTML row above the plot (line keys for lines, rect for columns, diamond for failed probes) with toggle-to-isolate buttons. Footer states the aggregation ('p95 and p50 across 40 targets, loss = mean'); percentile aggregation is client-side in the mock and not provided by the backend. Colours bind to metric id, never to rank.

**sparkline**

Not ECharts: a small SVG component (ui/meters/Sparkline), 64x24px, 2px stroke in --color-series-other, the newest real sample an 8px primary dot inside a 10px panel-colour ring, no axes, fixed 0-100 domain for percentages (a domain prop overrides it). A series is one entry per bucket, oldest left, with null where a bucket held no sample: a missing sample breaks the line (never bridged or interpolated), a lone sample is a dot, and a series that ends on a gap (the host stopped reporting) has no end dot but a hollow mark on its last sample and a dashed tail under the scale to the newest bucket, so silence is drawn and cannot be read as a value. Fewer than two samples draw a flat dash and 'no history'. Given the bucket times it can open a tooltip (on hover, or as one tab stop with the inspectable prop) carrying the figures its accessible name states; inside a link or button it does not, because the host already carries the numbers. Used only where the backend stores history: the Network targets tile (the hour's success rate from NetworkMeasurement: 12 points, no tooltip, aria-hidden beside the tile text) and the server detail Summary (CPU, RAM and disk beside each meter, from the per-server series the console API serves at servers/<id>/series/, the same series the history chart draws, requested once by the page). Servers and Docker tiles, the Servers list and Fleet load deliberately have no sparkline: the console API serves history per server, not for the fleet or for containers (ServerTelemetry stays one latest row per server, and a sparkline per row would cost one series request each), so no fake or partial trend is ever drawn; the tiles show a SegmentedBar instead. Planned tiles render none.

**bar**

Composition and utilisation are DOM/SVG, not canvas (cheaper, selectable, accessible): SegmentedBar and CellMeter as specified in the Meters component. Fleet load ranks the top 8 servers by CPU, RAM or DISK from the latest ServerTelemetry snapshot with one hue per state (cyan under 80, amber 80-94, red 95+), never a value ramp; ties sort by name; servers without a sample are excluded and named in the footer. ECharts columns (loss only on the Overview) use barMaxWidth 6px at 1-minute granularity (cap 24px elsewhere), a 2px radius at the data end and square at the baseline, bars grow from one baseline; a bar at or over the 2% loss limit carries a warning triangle above its tip so state is not colour-only. Value labels only at the extreme or last bar; the rest in tooltip and table. No pie or donut anywhere.

**tooltip**

One DOM tooltip for all series at the hovered x: crosshair is a 1px solid --color-border-control vertical hairline that snaps to the nearest sample (axisPointer type line, snap true), so readers aim at a time rather than a pixel. Content is built as an HTMLElement with textContent (never innerHTML; target names are untrusted API data) and returned from the tooltip formatter. Layout: timestamp (--text-data fg-faint, UTC or local per toggle), then one row per visible series (p95, p50, loss and failed probes): a key swatch in the series colour (12x2px for a line) + series name (fg-muted) + value (--text-data-strong, right-aligned, with unit), values lead and labels follow, the failed-probes value reading '2 of 60'. A value past its limit adds a line of its own under its row, led by a warning triangle, in words ('62 ms over warn'; '0.3% over warn', or 'at warn' when loss equals the limit); a missing value reads 'no data'. Panel-raised fill, 1px border-strong, 4px radius, 8px padding, confine true, transitionDuration 0, hide delay 100 ms. The same tooltip appears on keyboard focus (Left/Right/Home/End move the crosshair through dispatchAction showTip). Fleet load rows are focusable hit areas at least 28px tall showing server, metric, value and the sample timestamp.

**axesAndGrid**

Horizontal gridlines only, solid 1px --color-chart-grid; x baseline 1px --color-border; no tick marks, no vertical gridlines, no axis names (units sit in tick labels). Tick labels --text-chart 11px mono in fg-faint, never rotated and never clipped (ECharts hides alternate labels if five do not fit). Y axis: round 1-2-5 ticks starting at 0 for latency and loss, thousands separators. The latency axis takes at most four intervals (0, 50, 100, 150, 200 ms) up to the largest of the limit with 10% room above it (165 ms), the largest p95 and the largest p50, raised further when a worst spike needs room inside the grid for its triangle and label. The loss axis is max(2.2%, data) in at most two intervals, so 0 to 4% when loss is low, which leaves the limit label room above its line. Time axis HH:mm in the active timezone, labels only on the bottom grid. Grid insets: left 44, right 56 (end labels), top 8, bottom 28. ## Motion
Subtle and functional; motion only explains change and is fully removed under prefers-reduced-motion (and the Display menu override). Tokens: --ease-out cubic-bezier(0.2, 0.8, 0.2, 1); durations 80ms (hover, press), 120ms (overlay open/close with a 4px translate and fade, row enter and exit), 160ms (sidebar width), 300ms (chart update), 400ms (chart first draw), 600ms (value flash). Rules: (1) Refresh hairline: the 1px line under the topbar fills left to right over the poll interval with transform scaleX (GPU only), resets on each load, pauses when p freezes the screen, and is replaced by the static status-bar text 'next poll 12s' under reduced motion; it is a progress indicator, not a decorative loop. (2) Value change: a changed number or cell flashes --color-primary-tint (all text tokens pass AA on it, faint 4.69:1) and fades to transparent over 600ms; unchanged cells never animate; numbers do not tween or count up. (3) New CRIT row: inserted at its sorted position with a 120ms enter and one 1.2 s inset critical outline fade, once, never a loop and never a background change; no flashing above 3 Hz and no blinking anywhere. (4) Live cursor: solid when live; a 1 Hz stepped blink only while a request is in flight (under reduced motion it stays solid and the chip says 'updating'). There is no looping freshness pulse. (5) Skeleton: a 1.6 s opacity pulse on first load only, after a 150ms delay, static under reduced motion. (6) Charts: 400ms first draw, 300ms updates, cubicOut, off under reduced motion. (7) Refetch fades previous content to 60% over 120ms and back; layout never shifts. (8) Sidebar collapse 160ms width transition; wall-mode switch is instant (toggled from across a room). (9) Paused state stops all update animations and shows the PAUSED pill. (10) Title and favicon changes are instant. No parallax, scanlines, typewriter text or auto-rotating pages. OLED burn-in is mitigated by a static layout and no large bright areas (the brightest elements are 6-10px glyphs and 1px lines); an opt-in audible cue for new CRIT is a future setting, off by default.

## Decisions

- **Read the Overview in a fixed order: Tier-0 verdict hero, Tier-1 cross-domain Needs attention queue built from implemented state, Tier-2 charts and health, Tier-3 planned alerts and events; panel keys [1]-[6], j/k/Enter, n/N next problem.** It is the only layout that gives a real 'what is wrong now' list while alerts and events are not implemented, and it makes alert-to-detail two keystrokes. B and C answer the question with glyph cells you must hover.
- **Trust behaviours: stale guard at 45 s / 120 s using the client clock (useResource.updatedAt) plus generatedAt; order lock limited to row order while the queue is focused or the pointer moved within 5 s; verdict, title, badges and announcer always live; r applies queued updates at once, 30 s auto-apply; p pauses.** A frozen wall mouse or focused row must never delay a new CRIT; the dead-dashboard guard is the cheapest defence against a screen that still says green.
- **Scale wall mode with the root font size: clamp(16px, min(100vw / 90, 100vh / 56.25), 40px) and verify 1440x900 = 16px, 1920x1080 = 19.2px, 2560x1440 = 25.6px, 3840x2160 = 38.4px.** A product of two lengths (calc(16px * min(...))) is rejected by CSS.supports, so it would never scale; this form is valid everywhere and keeps one layout (1600x900 design box) from 1080p to 4K.
- **Re-derive the Overview geometry with slack: strip 120px (verdict and tiles need 112), main 676px, left rows 340 + 12 + 324, right rows 308 + 12 + 166 + 12 + 178, all checked against min-content by a script, using grid rows minmax(min, min-fr) so taller viewports stretch and shorter ones scroll the content area.** A 104px strip cannot hold 112px of verdict content, and three panels would overshoot by 4-8px. The vertical budget still sums to exactly 900 (12+120+12+676+12 = 832 plus topbar 44 and status bar 24) and the no-scroll claim is now stated for 900px-tall viewports only.
- **Make glyph + word the verdict hero at 24px/24px beside the 48px figure (instead of an 11px label), widen the edge to 4px, keep the figure in text colour; hero figures and KPI values in JetBrains Mono with negative tracking.** At 5 m only a large, status-coloured word carries severity; mono keeps one terminal voice and figures are at most 3 digits. This is a documented deviation from the dataviz proportional-figure guidance.
- **Use JetBrains Mono (static 400/500, latin + latin-ext + greek) with IBM Plex Sans (static 400/600, same subsets) instead of IBM Plex Mono; all shapes are SVG.** Verified against the published packages: @fontsource/ibm-plex-mono ships no greek subset while jetbrains-mono and ibm-plex-sans do, and the project's likely estate is Greek. Latin subsets contain no U+25xx glyphs, so shapes and cursors must be SVG.
- **Nav items, buttons and tabs are set in mono (--text-data-strong); Plex Sans is reserved for prose, names and titles.** Sans chrome dilutes the terminal voice and reads as polished dark SaaS; the mono/sans rule (machine voice vs human voice) is simpler to enforce.
- **Status alphabet is SVG circle / triangle / diamond / hollow square / bar / ring with 4-letter words; OFFLINE is a presentation of critical, not a sixth health status: anything that decides reads HealthStatus, and marks that describe an entity or a composition show offline apart; IDLE is a neutral fg-muted bar (never cyan); PLANNED and MOCK are provenance markers, not health states; the freshness chip uses a block cursor (solid, hollow, struck) instead of the OK circle.** Cyan already means focus, link, selection and series 1, and the OK shape must never mean 'data is fresh'. Keeping health shapes exclusive to entity health prevents a stale screen from reading as healthy. An agent that stopped reporting is a different fact from a failing resource, so it gets its own silhouette, word and hue (cool and low in chroma, so it never competes with CRIT); keeping it inside critical for every count that drives something means no filter, badge or verdict can disagree with the queue.
- **Quiet healthy with the exact #42D99B: no tint, no row edge, no word in dense strips, 6px dot in EntityCells, 6-8px bar segments. Dimmed variants of the green are rejected.** The brief requires the fixed palette values as-is. Size and the absence of tint make healthy recede while WARN and CRIT get glyph, word, tint and edge.
- **Health panel [4] = domain SegmentedBar rows plus BY SITE rows of EntityCells glyph strips (worst site first, strip up to 20 entities then bar + counts); the 20px-cell / 24px-pitch interactive grid is specified as the grid variant for Servers, Docker and Customers & Sites.** A matrix silhouette on the Overview is deferred. A 395px rail cannot hold 24px interactive cells, so the Overview strip is decorative inside one interactive row (row aria-label names every non-OK entity) and the accessible grid is reused where there is room.
- **Flag site grouping as sample data (SITE column dagger, BY SITE PLANNED marker, new 'site-links' feature entry, column and section auto-hide in the live adapter).** Only Device has a Site FK; Server and NetworkTarget do not (NetworkTarget.customer_name is free text). No proposal caught that grouping servers, containers and targets by site is unimplemented.
- **Container mapping in lib/status.ts: running+unhealthy and dead = CRIT; restarting = WARN; exited, created, paused and running+starting = IDLE (hidden from the queue by default); unknown state or unavailable host = UNKN. Details use only ingested fields (no exit codes, no restart counts).** Treating exited as WARN would raise false alarms for batch containers, and the backend has no expected-state field. IDLE keeps them one toggle away; the product question is recorded in risks and openQuestions.
- **Target classification: 3 consecutive failed measurements = CRIT; latest success with loss 2% or more or latency over 150 ms = WARN; expected_sla_percentage is not used.** The model documents expected_sla_percentage as informational and not calculated, so comparing rolling success with it would rest on a non-existent rule.
- **Server classification = Server.effective_status raised by UI resource thresholds (80% warn, 95% crit) so the Fleet load panel and the verdict agree; the reference dataset reconciles exactly (16 servers: 13 ok, 2 warn, 1 crit; 124 entities, 121 counted, 4 crit, 5 warn, 112 ok, 3 idle).** Every number on the Overview must agree across tile, bar, queue and meters; the geometry script also asserts these totals.
- **AGE honesty: servers and containers show time since last seen, targets show time since the first failed measurement of the run, threshold-derived warnings show an em dash; server details use only ingested fields.** The backend stores no state-change timestamps; inventing 'since 41m' for a disk warning would be fabrication.
- **No sparklines or trend lines in the Servers list, Fleet load, the tiles or for containers; the sparklines are the network success rate (history exists in NetworkMeasurement) and a server's own CPU, RAM and disk on its detail Summary (the console API serves that history per server); fleet composition shows SegmentedBars.** No fleet-wide history is served, DockerContainer is latest state, and a sparkline per row would cost one series request each; a trend there would imply a capability that does not exist.
- **Chart encoding: p95 in primary cyan as the lead series, p50 in slate, packet loss as azure columns in a second linked grid (never dual axis), SOLID warn lines, one per grid (150 ms latency, 2% loss; dashed is reserved for planned), warning triangles on samples past a limit and a label on the worst spike, failed probes as gaps plus critical diamonds, table twin on v.** p95 is the figure operators act on; emphasis encoding beats a rainbow; one line style per meaning keeps 'planned' unambiguous; a limit is judged once, in the model, so the mark, the tooltip, the table and the summary agree.
- **Statusline mode block (NORMAL, INSERT, pending chord) and shell-path breadcrumb with a live block cursor (solid, hollow, 1 Hz blink only while fetching, struck when stale); the prompt grammar is limited to the breadcrumb and palette input, not loading or verdict copy.** The mode block is derived from existing hotkey state (no extra machine) and makes single-key shortcuts safe and WCAG 2.1.4-friendly; the extra '$ fetch ...' copy was costume.
- **Log-line EventLog with a tree guide nesting recovery under failure; per-panel header tag 'mock · 15s' (source + interval); block-text twin of meters and a y copy-row action.** Fixed columns scan by eye, the tree guide shows cause and effect in the Log (the Timeline view shows when and for how long), per-panel age catches partial failure that one topbar chip hides, and the twin lets an operator paste a row into a ticket.
- **A Timeline view beside the Log in Recent events, with incidents derived client-side from the log's own events (an opener is a warning or critical event with no parent, closed by the first healthy descendant); the timeline inherits the panel's PLANNED chrome.** It answers 'what failed, what recovered, what is still open' without a new endpoint and without knowing anything the log does not show. A real incident or alert API would replace the derivation (docs/data-requirements.md).
- **Token governance: one semantic token layer in a single @theme static block with --color-*: initial, a vitest contrast test parsing tokens.css, a vitest ban on hex literals, a vitest grep keeping status colour utilities inside ui/status, ui/meters and charts, a /_ds dev route, and one buildChartTheme() reading getComputedStyle.** @theme static guarantees every variable exists for ECharts and SVG; one layer is enough for a dark-first v1 and matches frontend/docs/architecture.md ('token contrast is asserted in a test'). A plain @theme would skip unreferenced variables.
- **Provenance derived from SentinelApi.source and config/features.ts through a required features prop on Panel and StatTile; neutral hatched MOCK chip, dashed PLANNED frames, no new hue, no viewport rail.** The fixed palette allows derived neutrals and tints only; the markers survive screenshots through line style and words, and one registry entry flips them per feature.
- **Mock scenarios extend the existing ?mock= set (normal, slow, loading, empty, error) with healthy, outage, stale and partial, selectable from the palette; the default 'normal' is the reference dataset with a scripted deterministic timeline.** Every verdict state and every loading, empty, error and stale panel can be reviewed and screenshot reproducibly without a backend.
- **Drop TanStack Query; split getOverview into per-panel SentinelApi methods polled by the existing useResource (keepPreviousData, retry, visibility pause, updatedAt).** The repo deliberately excludes TanStack Query and already has useResource; per-panel resources give each panel its own loading, empty and error state, which the brief requires.
- **Hotkeys match by event.code for letters and digits, punctuation shortcuts have non-punctuation alternates, chords come from NAV_ITEMS (SNMP is g p), Space is not a global key (p pauses), and a native <dialog> palette gets a jsdom showModal shim.** Greek and Cyrillic layouts would silently break event.key letter shortcuts; Space must keep native activation and scrolling; nav.ts is the single source of chords.
- **Time ranges are 15m, 1h, 6h, 24h (the existing RangeKey) with 1h default; 7d is deferred to the Network screen.** Aligns with the existing view-model; probe retention for 7d is unknown and the Overview is a glance surface.
- **Ship dark only: no light theme, chart-pattern or motion attributes, or CSV export; with the semantic token layer kept so light can be added by redefining --color-* later. Defer InspectorDrawer, NEW tags, wall-mode toggle, density switch and prefers-contrast overrides to a later release.** A light theme would remap the mandated hexes and multiply the test matrix; the Overview must ship first. Geometry is rem-based from day one, so wall mode is a later one-attribute switch.
- **border-control is #697A86 so every control outline meets 3:1 on bg, panel, raised, hover and selected (3.22 on the selected tint); the value-change flash reuses the 12% primary tint (faint text 4.69:1); the new-CRIT flash is an outline fade, not a background.** Removing the failing pairs by construction is simpler than a placement rule people must remember, and it is covered by the contrast test.
- **Keep 60% opacity refetch behaviour, 150 ms-delayed skeletons, last-good data under a non-blocking error banner, native <dialog> and <select>, rem-based tokens (--row-h, --pad, --gap, --hit).** Consistent state handling across all panels with zero layout jump; native elements give focus management and mobile behaviour for free.

## Open questions

- Backend: should the Docker ingest carry an expected-state or restart-policy field (and exit code) so a crashed container can be told apart from a finished batch job? Until then exited maps to IDLE and is hidden from the queue by default.
- Backend: should Server and NetworkTarget gain a Site FK (only Device.site exists today)? Until then site grouping is sample data and the SITE column and BY SITE section hide in the live adapter.
- Backend: will the read API provide latency percentile aggregation (p50/p95 per bucket) and per-target state-change timestamps, or must the client reduce raw NetworkMeasurement rows?
- Product: when the alerts engine ships, does the verdict stay state-derived with an added alerts term, or does it become alert-derived? The design assumes state-derived with an additive term.
- Product: should criticality be configurable (tags, minimum counts) so one non-essential host going down does not paint the whole verdict CRITICAL? Out of scope until alert rules exist.

## Risks

- Palette limits: healthy/warning/critical are only 8.4-9.1 dE apart under protan/deutan and cyan vs green is 11.5 normal / 3.2 tritan. Shape plus word is the only safeguard, so it is enforced in code (vitest grep that status colour utilities appear only in ui/status, ui/meters and charts/theme) and must also be reviewed with a CVD simulator and a grayscale screenshot on /_ds.
- Cyan #64D8E8 (OKLab L 0.82) is brighter than the dataviz dark band and can glare on a wall display. It is confined to 2px marks, cursors, rings and 12% tints, never large fills. Large exact-#42D99B fills are limited to 6-8px bar segments; if the 112-segment green run in the verdict bar proves too loud on a wall, the fix is a thinner bar, not a dimmer hex (the palette is mandated).
- Critical #F16B73 is the weakest text colour (4.83:1 on selected rows). The rules that keep it AA (own 12% tint or plain surfaces only, no status text on tints of 18% or more, flash and selected share one 12% tint) must be encoded in component variants and the contrast test or regressions will creep in.
- Backend gaps shape the UI: the console API serves the session, scope, servers, containers and per-server resource history, network targets and SNMP devices (with their interfaces and history), and nothing for alerts or events; no alerts, events or state-change history; servers and containers keep only their latest state, so AGE degrades to last seen or an em dash and containers and the fleet have no trend (a server's own CPU, RAM and disk history is stored as telemetry samples and served per server; ServerTelemetry stays one latest row per server); no percentile aggregation; the console does not read site assignment yet, so the SITE column and the BY SITE strips are sample data; Docker exit codes and restart counts are not ingested; NetworkTarget.expected_sla_percentage is informational. The real adapter must supply these or the UI degrades (hides the column, shows an em dash) rather than fabricates. Thresholds (80/95%, 150 ms, 2% loss, 3 failures) are presentational and may later disagree with alert rules.
- Verdict semantics: counting only implemented domains means a future alerts engine will disagree with the derived verdict until reconciled; the plan keeps the verdict state-derived and adds an alerts term only when the engine ships. 'NOMINAL' while SNMP and alerts are blind is mitigated by the verdict tooltip, the PLANNED panels and the explicit exclusion wording, but needs product copy review. A single non-essential host going down paints the whole block CRITICAL: configurable criticality (tags, minimum counts) belongs with the alert rules.
- exited maps to IDLE (hidden from the queue by default) because the backend cannot tell an intended exit from a crash; a crashed batch or service container therefore needs the '+N hidden (idle)' toggle or the Docker screen to be noticed. The product fix is an expected-state or restart-policy field in the Docker ingest; until then the mapping lives in one place (lib/status.ts) with tests so it is cheap to change.
- Keyboard model: single-character shortcuts conflict with screen-reader browse-mode quick navigation and with browser shortcuts (Ctrl+K focuses the Firefox search bar, Ctrl+B opens bookmarks). Mitigations: matched by event.code so Greek and Cyrillic layouts work, ignored in fields and with Ctrl/Alt/Meta, a global off switch, every action reachable by button or palette (WCAG 2.1.4), preventDefault only while the app has focus; test with NVDA and VoiceOver.
- Live-update ergonomics are the highest-impact UX risk: a queue that re-sorts under the cursor causes mis-clicks during an incident, while a queue that freezes can hide a new CRIT. The rule (lock only row order on focus or recent pointer movement; verdict, title, badges and announcer stay live; r applies at once; 30 s auto-apply; no hover lock in wall mode) needs real interaction tests: hover, focus, removal of the selected row, selection restore by entity id.
- Typography: JetBrains Mono is 0.6em wide, so 12px mono at 801px leaves about 41 characters for DETAIL (sans, so about 47); long messages truncate and rely on the title tooltip and the deferred inspector. Latin, Latin Extended and Greek subsets are bundled; Cyrillic needs extra cyrillic-*.css imports; CJK hostnames fall back to the system font and may misalign columns. 11px is the floor; wall mode relies on all sizes being rem-based and on ECharts re-initialising when the root size changes.
- ECharts weight: even modular, the canvas chart chunk is the largest asset; it is lazy-loaded and limited to line, bar, grid, tooltip, axisPointer, markLine and aria, with sparklines, meters and bars in plain SVG/DOM. Verify the budget with a bundle visualiser and confirm tooltip HTMLElement formatter and dispatchAction showTip behaviour against the pinned ECharts 6.1 version.
- Scale and no-scroll: the no-scroll guarantee holds at a viewport 900px tall or taller (or wall mode at 1600x900 design box and above); on a typical 768-800px laptop viewport the content area scrolls about 100-130px, which is why verdict, strip and queue come first. EntityCells strips cap at 20 entities per site row; hundreds of sites need virtualisation and a search-first workflow (palette).
- Wall-display realities not designed here: OLED burn-in (static layout, no large bright areas, consider optional pixel shift), audio cues (future opt-in), multi-monitor layouts. Dark-only v1 leaves bright-office use unaddressed: the mandated status hexes are dark-tuned (healthy on white is about 1.8:1), so a light theme is a separate token mapping that needs its own design sign-off.
- Provenance chrome adds a chip, a status-bar line, per-panel tags and dashed frames; if it becomes noise people stop reading it. It is kept quiet (11px faint tags, no colour, one marker per tile) and wired from the registry so it vanishes per resource as the backend ships; forgetting to flip a FEATURES entry when a backend feature lands is the failure mode (add it to each backend API task's checklist).
- Scaffold drift: the repo's frontend/ already contains architecture.md, a single getOverview() view-model, 4-value HealthStatus, RangeKey 15m-24h and nav chords. Implementing this design means splitting getOverview into per-panel methods (so each panel has its own loading/error state), adding 'idle' to HealthStatus and the status mapping (the current mapping treats running+unhealthy as warning and exited as unknown), and keeping the existing useResource (no TanStack Query).
